## Scope and actual policy limits

Master-Spec sections 9–10/13.2 require broker entry price/volume, bid for BUY and ask for SELL, exact tick grids, stop/freeze distances, position revision and honest currency. The existing GoldM15 guard reader explicitly says its persisted file has no heartbeat and is not current authorization; Titan likewise has no verified action policy. Default guard is therefore UNKNOWN, source NONE, with a clear commit block. A client's guard flag, file mtime, UI version string or successful calculation must never grant permission. Native mouse/touch drafts and a real commit remain separate tasks.

This feature's numeric policy is explicit: plain decimal strings at most 32 characters, at most 12 fractional places, positive magnitude <=1e12 for prices/quote/point/tick size, volume<=1e9, and nonnegative stop/freeze levels<=2^31-1. Unsupported actual broker metadata returns NUMERIC_POLICY_UNSUPPORTED; it does not get rounded into support. Use local Decimal precision 64 for arithmetic. Before MT5 conversion, require positive finite double values, Decimal string roundtrip error<=one hundredth of the tick/volume step and double ULP<=one quarter of that step; otherwise PRECISION_UNSUPPORTED. These conservative limits are a preview capability policy, not a claim about all MT5 instruments.

Preview quote policy is stricter than legacy read models: normalized quote milliseconds may be at most 500ms ahead of server observation and at most 5000ms old, inclusive; reject beyond either boundary at the initial and final read. Expose the thresholds and measured signed skew/age. The existing 30-second read freshness and legacy contracts stay unchanged. A small permitted positive clock skew is labeled explicitly, not claimed to be exact now; as-of/expiry use server UTC.

Official contracts: [symbol properties and order flags](https://www.mql5.com/en/docs/constants/environment_state/marketinfoconstants), [broker order_calc_profit](https://www.mql5.com/en/docs/python_metatrader5/mt5ordercalcprofit_py).

The installed Python SDK does not export SYMBOL_ORDER_SL/TP constants. Use documented named masks SL=16 and TP=32 against the actual nonnegative integer order_mode, with the official reference beside the definitions; reject missing/non-integer metadata. Volume and its positive volume_step use the same 32-character/12-place decimal policy, with volume <=1e9. Check volume double precision against that actual step, and price precision against actual trade_tick_size.
