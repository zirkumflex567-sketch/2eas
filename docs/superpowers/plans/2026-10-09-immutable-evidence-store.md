# Immutable evidence-store Phase-0 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development and test-driven-development, then independent spec and quality review.

**Goal:** Deliver the first testable recording/provider boundary for DecisionEvent, TradeLifecycleEvent and TradeSnapshot, preserving absent-history semantics and account isolation. Actual EA instrumentation, background capture and UI remain subsequent tasks.

**Architecture:** Strict versioned models feed a bounded internal append-only SQLite store; public routes expose scoped reads only. No client ingestion, broker mutation or inference of historical decisions. The store is opt-in at an explicit private path; an unconfigured store reports NOT_RECORDED without creating files. Reuse verified dashboard identity and configured account identity, with no default shared principal or account.

**Tech Stack:** Python/FastAPI/Pydantic, SQLite transactions, canonical JSON/SHA256, bounded signed cursor, pytest temporary databases and installed security middleware.

## Executable contract appendix

### Common types and envelope

ID is ASCII `[A-Za-z0-9_-]{1,64}`; strategy/rule/reason ID uses that grammar. Symbol is broker_symbol's existing bounded validated string. Hash is lowercase 64 hex. Ticket is `[1-9][0-9]{0,19}`. UTC is an aware Z/+00:00 timestamp normalized to fixed six-fraction Z form and integer microseconds for ordering. Decimal price/volume is plain unsigned text, <=32 chars/12 fractional places, positive <=1e12; money permits a leading minus and zero within the same absolute bound. Feature value is finite int/float <=1e12 magnitude (bool rejected). Timeframe enum: M1/M5/M15/M30/H1/H4/D1/W1/MN1. Unknown/root extra keys reject.

Every stored record has an envelope `{schemaVersion:1, type:DECISION|LIFECYCLE|SNAPSHOT, id:ID, accountId:known account, brokerServer:configured label, terminalIdentityHash:Hash, dataRevision:int 1..2^31-1, provenance:RECORDED|RECONSTRUCTED, supersedes:RecordRef|null, payload:typed model}`. A RecordRef is `{type,id,dataRevision}` and implicitly has the enclosing account/terminal. Model identity fields must agree with the envelope. EvidenceRef additionally has its mandatory id:ID. Canonical JSON is UTF-8, sorted keys, compact separators, ensure_ascii=False, allow_nan=False after typed normalization; SHA256 covers the complete envelope including provenance/references, never the database sequence. Duplicate-key input parsing rejects before model construction. The grammar/typed allowlist excludes credential/path field names; do not pretend arbitrary free text can be guaranteed secret-free. No free-form notes in this phase.

Decision payload enums: stage CANDIDATE|SIGNAL|ENTRY_FILTER|RISK_GUARD|ORDER_ATTEMPT|BROKER_RESULT; outcome PASS|BLOCK|UNKNOWN. Feature is `{id:ID,value:finite number|null,unit:ID,timeframe:Timeframe}`; predicate is `{ruleId:ID,observedValue:finite number|null,comparator:GT|GE|LT|LE|EQ|NE|PRESENT,threshold:finite number|null,outcome:PASS|BLOCK|UNKNOWN,reasonCode:ID}`. Optional guardSnapshot is `{state:RECORDED|UNKNOWN,sourceRevision:Hash|null,checks:[{id:ID,outcome:PASS|BLOCK|UNKNOWN,value:decimal|null,limit:decimal|null}]}` with <=32 unique checks; UNKNOWN requires absent source revision. It records evidence, never permission. Feature/predicate IDs are unique within their lists. Decision dataProvenance is recorded|reconstructed and must agree with envelope provenance. Its dataRevision matches envelope integer.

Lifecycle payload follows the exact spec fields; eventType ENTRY|EXIT|PARTIAL_FILL|SL_CHANGED|TP_CHANGED|POSITION_OBSERVED, source MT5_DEAL|MT5_POSITION|EA_EVENT, actor EA|USER|BROKER|UNKNOWN, dataQuality OBSERVED|RECONSTRUCTED|UNAVAILABLE. revision is the envelope canonical payload hash computed from the payload before adding revision (exclude this self-hash field); envelope hash includes that final revision. Snapshot captureType ENTRY|EXIT|BACKFILL, renderStatus DATA_ONLY|RENDERED|UNAVAILABLE; renderAssetRef is null in this phase. chartView is `{symbol:Symbol,timeframe:Timeframe,fromUtc:UTC,toUtc:UTC,seriesType:CANDLE,priceScale:NORMAL|LOG}`, bounded ordered range<=31 days. marketDataRef is an EvidenceRef or null; indicatorInstanceRevisions is a <=256 list of `{id:ID,algorithmVersion:ID,parameterHash:Hash,sourceRevision:Hash}`; decisionEventIds is <=256 DECISION RecordRefs, not ambiguous bare IDs. Missing original decision/market references are explicit null/empty, never forged source objects.

Correction revision must be the latest same-account/terminal/type/id revision+1 and supersedes that exact previous RecordRef. First revision is 1 with supersedes=null. Snapshot decision references must exist under the same account/terminal with matching symbol and decision time<=snapshot as-of. Lists return ALL immutable revisions ordered by event time/id/revision; detail requires revision query for an original, otherwise explicitly returns latestRevision and that latest record. Cross-account references reject without existence disclosure.

### Authorization, storage and response boundaries

Route dependency reads exact verified request.state.control_identity tuple(channel,principal,role) and raw_peer; accepted roles read/layout/trade have read access to BOTH configured demo account aliases in this single-operator deployment. No per-account ACL exists, and no multi-user restricted account support is claimed. Missing/invalid identity403; missing/malformed account422; unknown configured account400. Explicit account is required before selected()/scope defaults; do not invoke MT5. terminalIdentityHash derives SHA256 over canonical JSON `[account id, decimal login, server, normalized configured terminal path]`; raw inputs never enter public records/URLs. All successes/errors have Cache-Control:no-store and canExecute=false. Unknown/wrong-scope detail404; bad cursor410; corrupt/unreadable store503.

Private DB must be an immediate child regular `.sqlite` file of an explicit CHART_STUDIO_EVIDENCE_ROOT outside every Git worktree and every StaticFiles mount. Root must pre-exist and be private: on Windows ACLs permit only the current user, SYSTEM and Administrators; POSIX root permissions0700/file0600. Check every path component with lstat, reject symlinks/reparse points and multi-link files, validate resolved parent for a not-yet-created file. Store takes the trusted local OS principal as the boundary (same-user filesystem attackers are not separable from the terminal operator). Revalidate root/file identity on every connection and fail after a detected replacement; do not claim race immunity against that trusted same user. No platform ACL verifier => explicit unsupported capability, not silent public storage. Read routes do not create a database: a reviewed trusted provider initializes an absent opted-in file. GET configured-but-not-created => NOT_RECORDED with storeState NOT_INITIALIZED; existing invalid files =>503.

Schema: metadata singleton(schemaVersion=1,generation random UUID); records(seq INTEGER PRIMARY KEY AUTOINCREMENT, account TEXT, terminal TEXT, kind TEXT, id TEXT, revision INTEGER, event_us INTEGER, symbol TEXT, strategy TEXT nullable, position_id TEXT nullable, canonical_json BLOB, sha256 TEXT, UNIQUE(account,terminal,kind,id,revision)). Index scoped order(account,terminal,kind,event_us,id,revision); filter indexes extend scope with symbol/strategy or position_id. refs(source_seq,target_seq) with foreign keys. Append uses BEGIN IMMEDIATE, rechecks count/identity/correction/references inside the same transaction, inserts record+refs, commits atomically. No public UPDATE/DELETE. Retry SQLITE_BUSY at most three attempts with busy_timeout=100ms and 50ms between attempts, <=500ms wall budget. Full-disk/max-page-count/conflict exceptions rollback and return structured errors; verify mode/page/max-page pragmas rather than assume unknown pragmas succeeded. Reject pre-existing -wal/-shm, never delete operator files. Reopening a valid rollback journal relies on SQLite recovery and then verifies hashes/schema. No ATTACH or user SQL.

Provider result is `{ok:bool,code:APPENDED|IDEMPOTENT|CONFLICT|RECORDING_CAPACITY|STORE_UNAVAILABLE,recordRef:RecordRef|null,gapObserved:bool,lostCount:int}`. Loss counter saturates at2^31-1 per account, <=known account count; it lives in process memory when DB cannot write, resets on restart and explicitly reports lifetime PROCESS_ONLY. No claim of durable loss accounting. Every read has coverage UNKNOWN, gaps `{knownLossSinceStart,lifetime:PROCESS_ONLY,unrecordedHistory:true}`. Unconfigured/empty/uninitialized: availability NOT_RECORDED. Nonempty page: RECORDED|RECONSTRUCTED|MIXED according to actual row provenance. STORE_UNAVAILABLE/capacity is never a false empty success.

Cursor payload<=1024 canonical bytes, total encoded<=2048: version,generation,scopeHash,pinnedMaxSeq,last tuple(event_us,id,revision,seq),expiresUtc. Scope includes verified identity/role/peer, account/terminal/kind and normalized filters/range. Random process HMAC key/constant-time check; TTL15 minutes, process restart invalidates. First read transaction atomically captures MAX(seq) and fetches the page under that pin. Use <=200 requested rows and <=2MiB aggregate record bytes per page, with cursor after the last returned record. No new correction/row with seq>pin appears later. Store generation replacement/expiry/scope mismatch/tamper=>410. Bounded offsetless SQL queries use indexes and pinned seq.
