# AT-030 Mutation Audit Log Implementation Plan

> **For agentic workers:** Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist a credential-free, append-only record for every state-changing dashboard request and its outcome, including ambiguous broker results.

**Architecture:** Add a small SQLite audit store with append-only triggers and an ASGI middleware for state-changing API requests. Record only canonical route, authenticated principal label/role, configured account alias, request ID, timestamps, HTTP outcome, and safe operation status; never persist headers, request bodies, cookies, passwords, tokens, login IDs, or server names. Existing commit-specific audit stores remain authoritative for their detailed idempotency/readback records; the new journal covers legacy broker mutations and local configuration writes.

**Tech Stack:** Python, FastAPI/Starlette ASGI middleware, SQLite, pytest.
