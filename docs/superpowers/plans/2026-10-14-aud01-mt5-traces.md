# AUD-01 bounded MT5 request spans

## Scope

Add low-overhead, in-memory timing spans for the account-session lock wait, MT5 initialization, identity verification, history reads, and rate reads. Keep a fixed-size request ring and at most 128 spans per request (counting additional dropped spans), with account alias only and no login/server/path/credentials. Expose snapshots only to an authenticated dashboard control identity with at least the read role. No persistent files, order-method instrumentation, MT5 launch, terminal switch outside normal request handling, or runtime restart.

## TDD sequence

1. Add unit contracts for nested span recording, bounded retention, request isolation, and safe fields; run them RED before implementation.
2. Add integration contracts for `scoped()` tracing of lock wait and initialize, and for timings around rate/history calls; run RED.
3. Implement a small ContextVar-backed recorder and instrument only existing read methods plus session initialization. Keep exceptions and endpoint results unchanged.
4. Add an authenticated read-only diagnostics route and tests proving anonymous access is denied, proxy read identity succeeds, invalid identity is denied, and no account identifiers or request payloads are exposed.
5. Run focused account/security/API tests, relevant Python regressions, and inspect production JS/API contracts for side effects. Instrument and test the Chart Studio portfolio correlation rate path and deliberate session-lock contention. Record that timings become available only after an approved app restart; do not restart/deploy here.

## Acceptance limits

Instrumentation and focused integration coverage are implemented. This does not establish a measured production baseline. AUD-01 remains partial until a clean deployment produces cold/warm/load traces and actual lock spans on the intended terminals. Existing P0 demo, write, hardware, and deployment gates remain in force.
