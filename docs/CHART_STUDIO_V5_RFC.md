# Chart Studio v5 Adapter RFC — staged migration (0.8)

**Decision:** pin `lightweight-charts@5.2.1`, `typescript@5.9.3` and `esbuild@0.25.12` in `chart_studio_v5/package.json`. This is an **opt-in, read-only renderer proof**, not yet a production switchover.

## Current integration and compatibility

- Existing dashboard, data feeds, EA signals, risk guards and all MT5 functionality continue using `static/lightweight-charts.js` (v4). **Do not change the active `app.py` Chart mount in this PR.**
- ChartStudioBeta's coordinate use now goes through an explicit v4/v5 adapter for epoch/BusinessDay time, price pixels, logical ranges and scope-bound crosshair/range callbacks. Node contract tests and Chromium smokes against the current v4 Beta and pinned native v5 bundle pass. Production remains mounted on v4; this interface does not claim native multi-symbol feeds or renderer parity.
- v5 replaces `chart.addLineSeries(options)` with `chart.addSeries(LineSeries, options)`, and likewise Candlestick/Histogram. v5 supports `addSeries(..., paneIndex)`, `moveToPane`, `chart.panes()`, and native pane height management.
- An independent native TypeScript adapter in `chart_studio_v5/src/adapter.ts` renders candles, moving averages, calculated RSI/ATR/MACD/ADX groups, native indicator panes and volume. Bounded oscillator formulas match the existing beta implementation; MACD/ADX components stay in one pane per logical indicator, settings/styles remain per instance, forming/new bars update the rendered tail, and account switches clear the groups. Browser contracts cover value/readout parity, flat and warm-up cases, same-kind independence, movement/removal, eight-pane and shared twenty-indicator limits. No broker routes are called; production wiring remains open.
- The isolated adapter also exposes a read-only exact-time data-window model: OHLC and real volume (or explicitly labeled tick-volume proxy), plus only line-series values whose timestamp exactly matches a loaded candle. Missing/warm-up data stays null, forming-bar updates invalidate indicator readouts, replacing history clears old values, and all fields identify the current account and `CHART_FEED` source. This is adapter capability only; no production sidebar/crosshair wiring is claimed.
- The isolated adapter renders horizontal price-level and vertical UTC-candle primitives. Their hit tests support selection and pointer-capture drag; horizontal lines follow the price coordinate, vertical lines snap to loaded bars, Escape restores the pre-drag anchor, and account/history changes cancel stale edits. A bounded history supports undo/redo, duplicate/delete and visibility/lock shortcuts. With an account/symbol/timeframe scope, private localStorage schema v2 restores drawings and strict undo/redo history across reloads; valid private schema-v1 snapshots migrate with empty history, while malformed history and external changes fail closed atomically. The portable JSON transfer format remains schema v1 and omits account identity and history. Chromium covers ordering, create/delete restoration, migration, malformed history and storage-write failure. This remains a renderer proof without full layout migration or production drawing integration.
- Native v5 trend-line, rectangle and Fibonacci start/end anchors now expose public-coordinate positions, render visible 12-pixel handles when selected and support endpoint pointer drags snapped to loaded candles. The untouched endpoint is preserved, Escape rolls back, locked drawings reject dragging, and one completed gesture is one history step; Chromium covers both anchors for each type and verifies selected trend handles render. Production tool wiring and v4 parity remain open.
- A CDP-injected touch sequence moves a native trend anchor in Chromium at 390 CSS px and 150% device-pixel ratio, including touch-start resolution when no hover object exists. This does not replace physical-device or Windows display-scaling acceptance.
- The isolated capacity fixture loads 5,000 bars, accepts a combined 20 overlay/pane indicators, creates/exports/schema-v1 imports 1,000 native drawings, persists/reloads all 1,000 under a 512-KiB UTF-8-byte-bounded snapshot, rejects drawing 1,001, and selects samples at the beginning, middle and end. A 523,385-byte private snapshot with 1,000 Fibonacci drawings exercises history trimming at the boundary and proves drawings remain intact; an over-limit multibyte snapshot is rejected by byte size. Chromium timings and limits are recorded in `docs/AT025_CHROMIUM_CAPACITY_2026-10-14.md`; they are headless-browser setup/readback evidence, not desktop/mobile FPS or input-latency acceptance.
- A native channel primitive renders baseline, translated boundary and dashed midpoint from three UTC/price anchors. The isolated Chromium proof covers strict creation/update/removal, all three public anchor positions, invalid/zero-width and unloaded-anchor rejection, lock/visibility API and pointer-lock rejection, shared 1,000-object accounting, undo/redo, scoped reload and schema-v1 JSON transfer. A vertical baseline is supported; stored anchors remain intact outside the current loaded window. Production tool wiring, v4 parity, channel touch acceptance and target-device acceptance remain open.
- The isolated adapter accepts a validated IANA display timezone for native v5 axis and crosshair formatting. UTC offsets distinguish both sides of the repeated autumn hour; Chromium verifies Berlin's spring and autumn transitions, atomic rejection of an invalid zone, and unchanged UTC readout, drawing anchor and pixel position. This is renderer capability only; production v5 wiring, actual MT5 session transitions and Windows/hardware acceptance remain open.
- The isolated adapter calculates managed EMA/SMA/WMA/RMA/SMMA overlays directly from loaded UTC candles, using the beta's OHLC source, seed/smoothing, display-shift and warm-up rules. It supports independent IDs/styles/configurations, recalculates after candle-history replacement, and incrementally updates affected points on forming/new bars. Exact-time values feed the native data-window readout. Chromium compares all five methods and each of the seven sources with `ChartStudioAverages.calculate`, sampling shift values from −2 to +2 across that matrix; it also checks two separately styled EMA-20 lines and rejects invalid periods. At 5,000 bars/20 indicators, the latest complete oscillator-group fixture measured 32.9 ms for one forming-bar update (single headless run); target hardware/performance acceptance remains open.
- Run: `npm install --prefix chart_studio_v5 --package-lock=false --no-audit --no-fund`, `npm --prefix chart_studio_v5 run check`, `npm --prefix chart_studio_v5 run build`, then `node scripts/smoke_chart_studio_v5.cjs` after installing the repository's Playwright Chromium dependencies. CI repeats these steps and stores a screenshot.
- Source is modular TypeScript. Generated `dist/` is not committed. No LWC 5 script or compiled bundles are shipped to production in this RFC.

## Follow-up: native pane lifecycle package (PR #25)

The opt-in adapter includes native v5 `addPaneLine`, `movePaneLine`, `resizePane` and `removePaneLine`, plus calculated RSI, ATR, MACD and ADX groups using the single chart's pane API. It caps logical oscillator panes at eight and all moving-average/pane/oscillator instances together at twenty, validates bounded settings, labels each native scale, and removes groups on account switch. On forming/new bars it recomputes formulas over the loaded history but updates only each native series' final point; cached calculator state and 150,000-bar endurance are still open. The browser proof checks beta calculation/readout parity, a grouped three-series MACD, isolated same-kind settings, native pane movement and resize, and limit rejection. This remains a renderer proof only; production editor/profile migration and v5 switchover remain open.

## Follow-up: native measurement drawing

The isolated v5 adapter supports a two-anchor measurement on exact loaded UTC candles. It displays signed price change, percent change and candle count, with no monetary P/L. The Chromium smoke captures the rendered label and covers endpoint drag with the opposite anchor preserved, keyboard nudging, Escape rollback, undo/redo, immediate atomic invalid-anchor rejection, the measurement's place in the shared 1,000-object limit and atomic 1,001 rejection, private account/symbol/timeframe reload, cross-account schema-v1 JSON transfer and mismatched symbol/timeframe rejection. Failed-import cleanup also detaches measurements. Production tool wiring, full parity, touch/DPI and target-device acceptance remain open.

## Follow-up: native CCI oscillator (2026-10-16)

The Beta and isolated v5 adapters now calculate CCI from typical price, period mean and mean absolute deviation with a 20-bar default and strict integer periods 2–200. Zero deviation yields zero; timestamps and warm-up values align to the candle that completes the period. The v5 stream uses a period-bounded window and a pre-forming-bar checkpoint, so repeated updates replace the same CCI point. The Chromium fixture compares batch and incremental outputs against the Beta formula through repeated forming updates and a new candle; it also verifies null warm-up readout, flat-window behavior, settings rebuild, history replacement, and persisted account/symbol/timeframe isolation. The shared 20-instance and 8-pane limits include CCI. Stochastic instance workspace validation was corrected to preserve its bounded period and smoothing settings. TypeScript, Node, workspace and Chromium checks pass. This is still an isolated renderer/math capability: production editor/profile wiring, renderer migration, desktop/mobile performance acceptance and rollback review remain open.
