# Isolated native Chart Studio v5 renderer

Experimental TypeScript browser adapter. **No MT5 access, broker mutation or dashboard cutover.**

The adapter also exposes `setPositionOverlays(snapshot)` / `readPositionOverlays()` for caller-supplied, read-only `MT5_VERIFIED` position snapshots. Each snapshot must match the renderer's account, symbol and timeframe and set `canExecute: false`; up to 500 unique tickets produce native Entry/SL/TP lines. Missing stops/targets remain absent. Invalid same-scope replacements preserve the current lines, while a scope mismatch clears them to avoid showing stale broker data. Account changes and destroy remove the lines. Position overlays are not user drawings and are excluded from persistence and portable JSON. This API does not fetch MT5 data and is not wired into production v4.

The optional `RISK_REWARD` drawing is placed with entry, stop and target anchors. It renders separate stop/target zones, an entry guide and a ratio derived from the three prices; invalid long/short ordering is rejected. The drawing supports handle editing, keyboard nudging, lock/visibility, undo/redo, duplication/deletion and the common 1,000-drawing limit. It is included in schema-v5 local persistence and portable schema-v2 layout transfer, while the production v4 chart remains authoritative.

The optional `FIB_FAN` drawing uses two distinct loaded candle/price anchors and projects the default 0.382/0.5/0.618 rays to the pane edge; callers may supply 1–16 strictly increasing ratios inside (0,1). It participates in the same scoped persistence, schema-v2 portable layout transfer, object manager, visibility/lock, undo/redo, duplicate/delete and 1,000-drawing limit as other native drawings. Preview placement and lifecycle actions are covered by the Chromium smoke; geometry, validation and CRUD history are covered by the adapter smoke. v5 remains opt-in.

The adapter also exposes `addMovingAverage` for independently configured EMA/SMA/WMA/RMA/SMMA overlays computed from loaded OHLC candles. It supports `close`, `open`, `high`, `low`, `hl2`, `hlc3` and `ohlc4`, periods 1–1,000 and display-only shifts from −500 to +500 bars. Replacing candle history recalculates managed instances; forming-bar updates use cached prior values and update only affected points. Exact-time data-window readouts preserve warm-up gaps. The smoke compares all five formulas and seven sources with the current beta calculation, samples shifts from −2 to +2, exercises same-bar/new-bar updates, and checks independent EMA-20 styles/configurations. This is calculation/rendering capability, not production editor/profile migration.

The adapter also exposes `addOscillator`, `updateOscillator`, `moveOscillator` and `removeOscillator` for bounded Wilder RSI/ATR/ADX, MACD, and Stochastic %K/%D groups. Stochastic supports a 2–200 bar range period and independent 1–100 bar K/D simple-average smoothing; flat ranges return a neutral 50 and warm-up bars remain empty. Parameters and colors remain instance-local; MACD's line, signal and histogram share a native pane, as do ADX/+DI/−DI and Stochastic %K/%D. Native price scales auto-scale and show axis/value labels. Each group keeps its rolling formula state and a checkpoint before the current candle. Repeated updates to a forming candle therefore replace its result from the unchanged prior state; a new candle advances the state once. Only the changed final native points and readout entries are updated. Replacing history or editing settings rebuilds the group. Chromium compares complete RSI/ATR/MACD/ADX/Stochastic outputs and UTC alignment against `ChartStudioIndicators.calculate` after repeated forming updates and a new candle, including flat prices, warm-up, invalid settings, config isolation, account cleanup, 8-pane and shared 20-indicator limits. Two 5,000-bar/20-indicator/1,000-drawing Headless Chromium runs measured 5.3 ms and 9.0 ms for a forming-bar update at 1280×840, DPR 1; this is environment-specific and not target-hardware acceptance. Native view state uses private account/symbol/timeframe-scoped localStorage schema v5 under the versioned `drawings:v5` key. It persists session-VWAP options alongside drawings, managed indicators, pane geometry and view settings. Valid schema-v1/v2/v3/v4 snapshots migrate into schema v5 while the prior `drawings:v4` key remains unchanged as a rollback copy. Session-VWAP settings survive reload, stay account-isolated, and participate in portable schema-v2 layout export/import and merge; Chromium covers persistence and migration. The compiled bundle is loaded by the opt-in, read-only v5 preview and by `fixture.html` in contract tests. The production dashboard chart stays on v4 until the separate gates in `docs/CHART_STUDIO_V5_RFC.md` pass.

Incremental oscillators and the chart model share a 150,000-candle hard history budget. Same-time forming-bar replacements continue at the limit; appending another candle fails before either the calculator or adapter mutates, so retained arrays cannot grow indefinitely. Use `setCandles` with the intended bounded window when a different history window is needed; recursive indicators are recalculated over that window.

The read-only `addAtrBands` / `updateAtrBands` / `removeAtrBands` API draws Upper/Middle/Lower using `SMA(close, 20) ± 2 × WilderATR(14)` by default. Both the full SMA and ATR warm-ups must be present; gaps are not forward-filled. Periods are bounded to 2–200 and the multiplier to 0.1–10 in 0.1 steps. Same-time candle updates replace the forming value, and the three-line group counts as one instance under the shared 20-indicator limit. The Beta comparison smoke covers exact series/readout parity, history replacement, invalid updates, collisions, removal, and account cleanup. The v5 preview remains isolated and gated off in production.

The preview also exposes the closed-bar `volume-range-median-v1` calculation and one native `setVolumeZones({timeframeSeconds, lookback, multiplier, visible}, {source: "MT5_VERIFIED", account, symbol, timeframe, timeUtc})` overlay.
